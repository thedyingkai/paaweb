# BESTI ACM 校队部署配置

本目录用于 `https://bestiacm.thedyingkai.cn`，安装目录为 `/opt/paaweb`，Compose 项目名为 `paaweb-school`。公网 Nginx 终止 TLS，应用网关只映射到 `127.0.0.1:3403`。数据库、文件卷和网络独立创建。

平台定位为北京电子科技学院 ACM 校队，使用用户选定的“校徽外圈 + ICPC 图形 + BESTI ACM”队标。队标原图保存为 `frontend/public/brand/besti-acm-logo-v1.png`，页面通过同一个品牌组件展示。保留上游软件的 LICENSE 和第三方声明。

## 构建

在有 Java 21、Maven、Docker 的工作站构建，将结果加载到服务器。这样生产主机不累积 Maven、npm 和 Docker 构建缓存。

```powershell
cd backend
mvn.cmd -B -s settings.xml package -DskipTests
cd ..
docker build --build-arg JRE_IMAGE=public.ecr.aws/docker/library/eclipse-temurin:21-jre-alpine -f backend/Dockerfile.prebuilt -t paaweb-school-backend:20261111-besti-r8 backend
docker build --build-arg NODE_IMAGE=public.ecr.aws/docker/library/node:24-bookworm-slim --build-arg PUBLIC_SITE_URL=https://bestiacm.thedyingkai.cn -t paaweb-school-frontend:20261111-besti-r8 frontend
```

`Dockerfile.prebuilt` 使用刚刚构建的 JAR。前端构建运行 Next.js 编译和 TypeScript 检查。官方镜像的 ECR 地址用于 Docker Hub 不可达的网络；可通过构建参数切换回 Docker Hub。

## 服务器配置

将仓库根目录的 Compose 文件、SQL、网关配置和管理脚本复制到服务器，把本目录的 `docker-compose.override.yml` 复制到部署根目录。首次运行 `bash scripts/init-env.sh`，然后在权限为 `0600` 的 `.env` 中设置：

```dotenv
COMPOSE_PROJECT_NAME=paaweb-school
HOST_BIND=127.0.0.1
HOST_PORT=3403
PUBLIC_SITE_URL=https://bestiacm.thedyingkai.cn
SERVER_SERVLET_SESSION_COOKIE_SECURE=true
JAVA_TOOL_OPTIONS=-Xms128m -Xmx512m -XX:+UseG1GC -XX:+ExitOnOutOfMemoryError
```

数据库密码由初始化脚本生成，不使用示例值。SMTP、QQ 机器人、爬虫和外部 OJ 需要各自配置；空配置不代表已接通这些服务。

确认 `172.30.34.0/24` 不与现有网络重叠。`gateway.conf` 基于通用网关，增加对宿主机地址 `172.30.34.1` 的真实来源 IP 和 HTTPS 转发支持；调整网段时必须同时更新两个网关配置文件。生产容器均有内存上限和日志轮转限制。

```bash
docker compose config --quiet
docker compose up -d --no-build --pull never db
# 数据库初始化完成后，通过 stdin 输入管理员新密码。
bash scripts/reset-admin-password.sh admin
docker compose up -d --no-build --pull never
```

在开放公网前更换初始化管理员密码，验证应用和管理员登录。随后安装 `bestiacm.thedyingkai.cn.conf` 到宿主机 Nginx 配置目录，运行 `nginx -t` 后 reload。公网配置保留 HTTP-01 验证路径，并将其他 HTTP 请求跳转到 HTTPS。

## TLS 与运行检查

证书使用独立的 ACME 账户和 HTTP-01 验证，密钥位于 `/opt/paaweb/tls`，该目录权限为 `0700`，私钥为 `0600`。`tools/acme_tiny.py` 使用 [acme-tiny](https://github.com/diafygi/acme-tiny) 的原始脚本。验证文件是公开的，需允许 Nginx 工作进程读取。

将本目录的 `paaweb-certificate.service` 和 `.timer` 安装到 `/etc/systemd/system/` 并启用 timer。续期脚本每天检查，在证书剩余不足 30 天时申请新证书，验证成功后替换并重新加载 Nginx；失败时保留可用证书。

```bash
docker compose ps
curl -fsS https://bestiacm.thedyingkai.cn/healthz
systemctl status paaweb-certificate.timer
df -h /
```

备份时保存 `paaweb-school_pg_data` 数据库、`paaweb-school_uploads` 上传文件及受保护的 `.env`、TLS 密钥；运行 `pg_dump` 获取一致的数据库备份。不要使用 `docker compose down -v` 删除业务卷。

## 校队模块升级

升级前使用 `pg_dump` 备份数据库，然后执行 `SQL/migration_besti_team_space.sql`。该迁移只新增校队档案、讨论与回复表，可重复执行；首次安装由 Compose 初始化挂载执行。

`/competitions` 说明赛事范围；`/team-space` 维护个人奖项、职务和参赛登记；`/community` 是仅已审核成员可访问的交流区。核验通过的奖项和职务显示在个人主页，私人补充材料和报名信息不公开。修改已经通过的记录会撤回公开展示，重新进入待核验。

赛事范围在前后端同时限制。联盟主办比赛、ICPC、CCPC、天梯赛允许有赛事管理权限的队长统一登记；蓝桥杯、马蹄杯、百度之星、CCSP、CNCC 仅本人自愿登记，批量接口拒绝这些类别。职务文字不影响系统权限。队长权限由管理后台分配，交流管理使用 `manage_user` 或 `manage_sys` 权限。

历史荣誉以 `docs/besti/records.json` 为可复核快照，通过管理员 `/api/intro/update` 写入 `honors` 类别，`metadata.json` 写入 `honors_meta`。统计以比赛队次计算，同场同队合并；来源歧义记录在元数据中。不要自动创建或绑定历史选手账号。

普通成员使用已有身份审核机制。SMTP 尚未配置时，邮箱验证码注册与账号激活不可用；部署完成不代表邮件功能已接通。管理员可在系统邮件配置中接入邮箱服务后开放成员注册。

## 普通参赛者、校队资格与院系专业（r7）

前后端均升级至 `20261111-besti-r7`。备份后执行 `SQL/migration_besti_academic_catalog.sql`，只补充缺失的院系与专业，保留已有 ID 和用户资料；数据来源及注册分组说明见 `docs/besti/academic-catalog.json`。本科覆盖四个系的八个现有专业，研究生专业在“研究生部”下单列，避免猜测各系的研究生培养归属。

学生卡审核只确认身份。通过后，普通参赛者可按赛事条件报名校赛、维护本人奖项、职务和参赛经历；个人入口统一为“我的参赛档案”。身份认证不会产生校队资格，自填职务或审核通过的职务经历也不会授予校队权限。

校队资格由有系统管理权限的管理员在“内容 → 校队成员”维护：记录组织必须为 ACM 校队，职务为校队队长或队员，绑定本人 userId，并处于有效任期。未绑定的历史展示资料、联盟负责人、未来或过期任期均不开放内部交流。解绑、删除或修改任期后，下一个请求按实时名单判定；学生身份未认证、受限或封禁账号不能进入。`manage_user` / `manage_sys` 管理员保留交流管理入口，但不因此被标记为校队成员。

交流区的所有列表、详情、发帖、回复、修改、删除及管理接口均检查资格。自助参赛档案与公开比赛报名继续使用学生身份认证，保持普通参赛者可用。注册、个人资料、后台审核和成员管理均说明两种资格；邮件标题、页脚、证书示例、榜单本校名称及旧素材地址均改用 BESTI ACM / 北京电子科技学院。

## 历史战绩归属（r10）

前后端升级为 `20261111-besti-r10`。备份数据库后执行 `SQL/migration_besti_history_claims.sql`，再启动新镜像。迁移新增历史归属、认领申请、操作日志，以及个人档案的历史来源和打星字段；可重复执行，不修改历史榜单，也不自动生成归属。回退镜像时保留这些新增表和字段即可。

成员从荣誉墙或“我的参赛档案”进入 `/history-awards`。学生身份审核通过后，可按实名认证姓名查找历史战绩，选择队员名额，填写参赛证明说明及可选证明链接，提交认领。管理员在 `/admin/history-awards` 核验学校、学号、姓名和证明后通过；记录随即显示在该成员的个人档案。原榜单没有队员名单时，提供三个待核验名额，必须由管理员查验证明。身份审核不会自动赋予校队资格。

具有 `manage_user` 或 `manage_sys` 权限的管理员可下载完整名单模板，填写学号后上传预检，也可逐人登记。导入仅处理已填写学号的行，严格匹配学校、学号、姓名三个字段；批次中有错误时整批不写入。已认证账号立即关联，未注册或未通过身份审核的记录保留为“待实名关联”，后续身份审核通过时自动关联。姓名相同不能单独作为自动分配依据，外部平台账号也不作为学号。完整名单模板含稳定战绩编号和队员序号，重导不会重复生成个人记录。

已关联的奖项保留 ICPC、CCPC 的赛事阶段、原始金银铜牌或优胜奖，按既有规则存储学校认定。打星等效奖项单列，不进入正式获奖计数；无奖的预赛等记录只作为参赛经历。历史归属只能由管理员核验撤销或重新登记，成员不能通过自填记录接口改写。撤销会停止个人档案展示并保留操作日志。身份信息变化后，旧归属停止展示，等待重新核验。此流程不会发邮件或签发证书。

归属写入通过事务锁和版本校验避免重复审核、并发覆盖；审核或导入前历史榜单发生变化时，要求刷新重做。成员接口只返回本人申请和公开榜单信息；他人的学号、认领证明及审核日志仅管理员可读。

## 经历与积分联动（r12）

前后端升级为 `20261112-besti-r12`，无表结构迁移。升级前备份数据库；服务启动后会按现有来源全量重算积分。未设置学期时累计全部历史比赛、已核验正式奖项与刷题分，不生成虚构学期；已有学期继续采用原有跨学期 20% 保留规则。未来学期与未来日期的数据不进入当前结算。

已核验成员奖项按 `certificate_level` 的级别、等次和基础分值计入奖项分。历史归属必须仍与通过实名审核的账号一致；打星、待审核、撤销及已失效归属不计正式奖项分。相同用户、赛事名称（忽略空格和大小写）、日期、级别及等次的证书与档案奖项仅计一次。刷题沿用每天 `round(log10(当日解题数 + 1) × 10)` 的规则，题号按平台区分并去重。奖项审核、名单导入、归属撤销和 OJ 同步结束后异步触发重算，事务回滚不触发，保留启动及每日重算兜底。

“经历”同时展示获奖比赛、打星参赛及普通参赛记录，并读取管理员正式名单中绑定该账号的任职；相同任职在个人档案中重复登记时不重复展示。任期继续按实际起止日计算，在任与“前”职务自动区分。这些内容仅作经历展示，不额外授予校队资格或账号权限。
